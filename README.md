# 网页采集配置管理工具

离线版采集配置管理工具，涵盖站点管理、抽取模板编排、代理池配置、限速策略、重试机制、增量采集与数据落盘规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。严格线性模块的越级/倒序
  动作会被服务端直接拒绝，并在提示中说明当前状态允许的下一步。
- 想回到初始数据：清掉浏览器里 `scraper-config-studio:entries` 这一项，或调用 `resetModule(模块)`。

### 网页模板版本状态机（template 模块）

模板不经过通用动作通道，统一由 `frontend/src/data/template-store.ts` 版本引擎管理：

- 状态只能按 **草稿 → 待校验 → 已启用 → 已废弃** 单向推进；已废弃是终态，不能再回到已启用。
- 「提交校验」前强制校验三个必填入口：入口地址、列表选择器、分页规则，缺失时逐条说明缺失项，
  不产生新版本。现场样本 TEMP-0017（列表选择器为空）即按此口径拦截。
- 「重新校验」基于当前版本生成 `rowVersion + 1` 的新草稿记录，旧版本只读保留；模板编号与
  历史字段不改写。同一模板编号只有 `rowVersion` 最大的一条是当前有效版本，其余为历史版本，
  列表/概览/导出的通用取数链路只镜像当前有效版本。
- 同模板同动作有进程内互斥锁，并发请求只接受首个；快速连点与重复提交不会生成第二版本。
- 校验通过时字段映射契约固化到版本记录；启用模板时契约同步写入「字段映射」业务面
  （extractor）生成已启用映射行，同模板旧映射行停用留痕；废弃模板时对应映射行同步停用，
  另一业务面只能引用当前有效版本。
- 动作执行前建立模板版本库与字段映射清单两份快照，提交失败整体回滚，并在返回值
  `retryFrom` 中给出可恢复位置。
- 复测可运行 `npm run verify`（共 70+ 条领域与同步断言，含 T-17、T-03 场景）。
